# 徒歩15分 駅マップ (walk15) 設計

- 日付: 2026-10-03
- 状態: 合意済み (2026-10-03、チャットで確認)
- リポジトリ: `eki-walk` (個人 GitHub で公開予定。公開データだけを使う)

## 1. 目的

地図で地点を選ぶと、そこから**歩く道のりで 15 分以内**に行ける駅と、駅ごとの徒歩分数を示す。
地図全体は「徒歩 15 分以内の駅の数」で塗り分け、駅の選択肢が多い所・少ない所を見せる。
想定する使い方は物件探しで「この部屋はどの駅が使えるか」を確かめること。対象はまず東京。

同じリポジトリに、のちに「鉄道空白地帯を等距離線で可視化する」アプリ (gap) を追加する。
道路網と駅のデータ作りは両アプリで共通にする。

依存の向きは `products` → (`reach`, `network`, `stations`, `sources`) の一方向だけ。
`reach` は「駅ごとに上限距離まで」(walk15) と「全駅から一度に、最寄り駅までの距離」(gap 用、v1 では作らない) の 2 つを持てる形にする。

## 5. 計算方法

座標は計算時に JGD2011 平面直角座標系 IX 系 (EPSG:6677) に変換してメートルで扱う。

### 5.1 範囲

- 対象範囲 (AOI): N03 の東京都から島しょ部 (大島・三宅・八丈・小笠原の各支庁) を除いた面。
- 駅: AOI から 1.5km 以内にホームがある駅をすべて入れる (都外の駅も含む)。
- 道路網: AOI を 3km 広げた範囲の外接矩形で取る。

### 5.2 歩ける道

- Overture segment のうち `subtype = road`。
- 除外: `class = motorway` (首都高・高速道路とそのランプ)、`access_restrictions` で徒歩が禁止されている道、工事中の道。
- 含める: 歩道・横断歩道・階段・歩行者道・地下通路など。
- `access_restrictions` の書き方は実データで値の分布を確かめてから判定ルールを決め、`docs/method.md` に記録する。
- 道は segment が持つ connector (ID と線上の位置 `at`) で分割し、connector を節点、分割した区間を辺 (長さ = 平面上の長さ m、向きなし) とするグラフにする。connector の型 (`type=connector`) のデータは取得しない。
- いちばん大きくつながった部分だけを使う (切れた断片に吸着して「0 駅」と出る誤りを防ぐ)。

### 5.3 駅

- N02 の駅地物 (路線ごとのホームの線) を単位にする。ID は駅コード `N02_005c`。
- 鋼索鉄道 (ケーブルカー) は除外する。都電・モノレール・新交通は含める。鉄道区分コードは実データで確認する。
- 駅の中心: ホームの線の中点 (線の長さの半分の位置)。
- まとめ方: グループコード `N02_005g` (300m 以内で同じ駅名の駅をまとめたもの) を「1 駅」とする。
  表示は「新宿: 丸ノ内線 4 分 / JR 7 分」のように路線ごとの分数も出し、駅の数は 1 と数える。

### 5.4 道のり

- 起点: 駅の中心から半径 R 以内にある節点すべて。初期値は中心からの直線距離。
  半径 R 以内に節点がなければ最寄りの節点 1 つ。R は 50m と 100m を検証地点で比べて決める (既定 100m)。
- 探索: 駅ごとに仮の起点節点を足し、`scipy.sparse.csgraph.dijkstra(limit=1200)` で 1,200m で打ち切る。
- 速さ: 80m = 1 分 (不動産の公正競争規約と同じ)。分数は切り上げ、最小 1 分。15 分以内 = 1,200m 以内。

### 5.5 格子

- H3 解像度 11 のセルのうち、中心が AOI に入るもの。
- セルの距離 = セル中心から最寄りの歩ける道の上の点までの直線距離 s + その点までの道のり。
  辺 (u, v)、長さ L、点の位置 t のとき、道のり = min(d(u) + t, d(v) + L − t)。
- s が 100m を超えるセル (大きな公園・川・操車場など) は「道から遠い」として答えを出さない。
- 駅のまとまりの距離 = そのまとまりに属する路線の距離のうち最小。

### 5.6 アプリ用に出すもの (すべて同じセルの値から作る)

1. 答えの表: セルごとの「路線ごとの駅 ID と道のり (m)」。H3 解像度 7 の親セルごとに 1 ファイル。
   形式はまず JSON。大きさを測り、重ければ詰めた形式にする。
2. 塗り分け: 15 分以内の駅の数 (1 / 2 / 3 / 4 / 5 以上) ごとにセルをまとめて面にし、単純化した GeoJSON。0 駅は塗らない。
3. 駅ごとの 15 分圏の輪郭: 駅のまとまりごとに、1,200m 以内のセルをまとめた面 (重なり可) の GeoJSON。
4. 駅の一覧: まとまりの ID・駅名・位置・属する路線 (事業者・路線名・駅コード) の JSON。
5. メタ情報: データの版・取得日・計算条件の JSON (画面の「出典」「限界」に表示)。

同じセルから作るので、クリックの答えと輪郭・塗りは必ず一致する。

## 6. 画面

- 全画面の地図。上部に「駅名で移動」の入力 (駅一覧から候補)、「現在地」ボタン、背景の切り替え (地図 / 航空写真)、凡例。
- 塗り分け: 圏内の駅の数 1 / 2 / 3 / 4 / 5+ の段階色 (半透明)。
- クリック (または現在地): 地点にピンを置き、結果パネルを出す (PC は右、スマホは下から)。
  - 「この地点から徒歩 15 分以内: N 駅」
  - 駅ごとに、いちばん近い路線の分数・距離、路線ごとの分数。分数の短い順。
  - 駅を選ぶと、その駅の 15 分圏の輪郭と駅の位置を強調する。圏内の駅の輪郭は細線で常に出す。
  - 対象範囲外なら「対象範囲外」、道から遠いセルなら「近くに歩ける道のデータがありません」と出す。
- 現在地はブラウザの中だけで使い、外へ送らない。
- 「この計算の限界」:
  - 距離はホームの中心から測っていて、駅の出口からではない。
  - 信号待ち・坂・階段・踏切・地下の上り下りは入れていない。
  - 80m = 1 分で換算している。
  - 道路データが欠けている所があり、私道の扱いは不確か。
  - 物件広告の「徒歩○分」(駅の出入口から物件の敷地まで) とは測り方が違う。
  - 地点は約 25m の格子にまとめている。
  - データの版と日付。
- 「出典」: OpenStreetMap contributors (ODbL)、Overture Maps Foundation、OpenFreeMap / OpenMapTiles、
  「国土数値情報（鉄道データ・行政区域データ）（国土交通省）を加工して作成」、地理院タイル。
- 外部へ送る通信は、背景地図のタイルと CDN のライブラリの取得だけ。

## 7. ライセンス

- コードとオリジナル文書: Apache-2.0。
- 生成データ (答えの表・輪郭・塗り): Overture (ODbL) から作った派生データベースなので ODbL で提供し、N02・N03 の出典も表示する。README と画面に書く。

## 8. 検証

- 単体テスト (pytest): 歩ける道の判定、connector での分割、起点付き打ち切り探索 (小さな手作りグラフ)、
  辺の途中の点の道のり、分数の切り上げ、駅のまとめ、セル → 親ファイルの引き当て。
- 実データの検証: 23 区内の 10 地点ほど (大きな駅の近く、線路沿い、川沿い、都境) で、
  地図上で道をたどって測った距離と比べ、`docs/validation.md` に記録する。R の値もここで決める。
- 画面: ブラウザで、クリック・駅名で移動・輪郭の強調・スマホ幅の表示を確かめる。

## 9. 進め方の約束

- ダウンロードは毎回、ファイル名・取得元・大きさを示して確認を取る。
- 依存の追加は `uv add`。
- コミット前に、生データ・秘密情報・大きなファイルが入っていないか確かめる。
- GitHub へのリポジトリ作成と push は、そのつど確認を取る。

## 10. やらないこと (v1)

住所検索、分数の切り替え、駅の出入口データ、信号・坂の考慮、ブラウザ内の経路探索、経路の線の表示、東京以外。

## 11. 実装時に変えたこと (2026-10-03)

- 島しょ部の除外: N03-2026 では東京都の `N03_002` (支庁名) が空だったため、`N03_007` (市区町村コード) で除く。所属未定地 (東京湾の埋立地、3.5km²) も除く。
- 駅: 同じ駅コードの線が複数の地物に分かれていたので、駅コードごとに 1 本にまとめてから中心を出す。
- 歩ける道: 廃道 (`is_abandoned`) も除く。
- 起点の半径: 50m と 100m を独立した徒歩ルート検索と比べ、50m に決めた (`docs/validation.md`)。
- 15 分圏の輪郭: 1 ファイルではなく駅ごとのファイル (`iso/<駅>.json`) にし、必要な分だけ読む。
- 塗りと輪郭の形は 10m で単純化 (クリックの答えには影響しない)。
- 画面: 背景地図の読み込み完了 (`load`) を待たず、スタイルを読んだ時点で重ねる層を足し、クリックも最初から受け付ける。
