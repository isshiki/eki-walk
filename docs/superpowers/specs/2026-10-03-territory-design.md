# 駅の縄張りマップ 設計

- 日付: 2026-10-03
- 状態: 方針は合意済み (2026-10-03、チャットで「全て推奨で」)。この文書の確認待ち
- 置き換えるもの: walk15 (徒歩15分 駅マップ)。walk15 の「15 分以内の駅の数」は、切り替えで出す副次的な表示にする
- 試作: 作業用フォルダで作った試作の画像 5 枚をチャットで共有済み (杉並〜中野、仮データ)

## 1. 目的

「自分の住んでいる所 (これから住む所) は、どの駅の勢力圏 (縄張り) に入るか」を地図で見せる。
主役は**駅ごとの縄張りを塗り分けた地図**。物件探しで「ここはどの駅の勢力圏か」をひと目で確かめられるようにする。

- 縄張り = 歩く道のりでいちばん近い駅の範囲 (道路網で測ったボロノイ分割)。
- 徒歩 15 分 (1,200m) 以内なら、複数の駅の勢力圏が重なってよい。
  例: A 駅まで 6 分・B 駅まで 12 分の所は「A 駅の縄張りで、B 駅の 15 分圏とも重なる」。

## 2. 決めたこと

| 項目 | 決定 |
|---|---|
| 縄張りの作り方 | 道路網の最短路で各地点の「いちばん近い駅」を決め、25m 格子から駅ごとの面を作る。境界は共有する線を 1 本ずつ平滑化する (隙間・重なりなし) |
| 色 | となり合う縄張りが別の色になるように、少ない色数 (6 色まで、試作では 4 色) で塗り分ける |
| 重なりの見せ方 | ふだんは「境界付近の帯」(2 番目に近い駅との差が 3 分以内) を斜線で重ねる。地点・駅を選んだときは、関係する駅の 15 分圏を破線で描く |
| 15 分を超える所 | 縄張りの色を薄くする |
| 乗換駅 | N02 のグループコードでまとめたうえで、同じ駅名で 600m 以内のものも 1 駅にまとめる (池袋・武蔵小杉・両国・東京・浅草が該当。早稲田 (都電、744m) は別) |
| 共通化 | 道路網・駅・最短路・格子は rail-gap-map の `ekiwalk` を使う (git 依存、commit 固定)。eki-walk は縄張りアプリだけの処理と画面を持つ |
| 道路網 | OpenStreetMap (Geofabrik 関東 `kanto-261001.osm.pbf`、2026-10-01)。Overture は使わなくなる |
| 名前と場所 | 「駅の縄張りマップ」。公開先は `https://isshiki.github.io/eki-walk/` (今の `walk15/` からはこちらへ案内する) |
| 位置・住所 | ブラウザの外へ送らない (現在地・検索とも、ブラウザの中だけで処理) |

## 3. rail-gap-map との共通化

### 3.1 `ekiwalk` から使うもの (変更せずに使う)

eki-walk に `ekiwalk` を git 依存として入れる (`uv add "rail-gap-map @ git+https://github.com/isshiki/rail-gap-map@4176263"`)。
commit は、この設計を書いた時点の GitHub 上の rail-gap-map の main (`4176263`) に固定する (rail-gap-map では別の作業が進んでいるため)。新しい commit に上げるときは、そのつど確認を取る。
`load_region(name, root=<eki-walk>)` に eki-walk の設定 (`configs/regions/tokyo.toml`) を渡し、中間ファイルは eki-walk の `data/build/tokyo/` に作る。

| 手順 | `ekiwalk` の処理 | 出力 |
|---|---|---|
| 道路網 | `network.run` (OSM の歩ける道。高速道路・`foot=no`・私道 (歩行者可以外) などを除き、いちばん大きくつながった部分) | `nodes.parquet` / `edges.parquet` |
| 水面 | `water.run` | `water.wkb` |
| 行政区域 | `admin.run` (N03 の 11・12・13・14。表示範囲は東京都から島しょ部を除いたもの) | `land.wkb` / `display.wkb` |
| 駅 | `stations.run` (N02 の駅。ホームの線) | `stations-base.parquet` |
| 最短路 | `shortest.solve` (全駅から一度に。ホームの線から 100m 以内の道の点を起点、距離はホームの線までの直線距離) | 節点ごとの「道のり」と「いちばん近い駅」 |
| 格子 | `surface` の考え方 (25m 正方格子、各格子はまわりの道の点 8 つのうち、道のり + 直線距離 が最小のもの。道から 300m 超・海・水面は空白) | `grid-base.npz` |
| 町丁目検索 | `places.run` (ABR の町字と代表点 + 駅) | `places.json` |

これにより、**どの格子が「いちばん近い駅」かは rail-gap-map と同じ**になる。

### 3.2 eki-walk で作るもの (`src/eki_walk/territory/`)

| モジュール | 役割 |
|---|---|
| `groups.py` | 駅のまとめ: N02 のグループコード → 同じ駅名で 600m 以内のグループを合わせる (union-find)。路線ごとの駅 → まとめた駅の対応表 |
| `reach.py` | 駅ごとの 1,200m 打ち切りの最短路。起点の付け方は `ekiwalk.shortest.solve` と同じ (ホームの線から 100m 以内の節点、重み = 線までの距離 + 1e-3) |
| `cells.py` | 格子ごとの「駅ごとの道のり」(15 分以内のもの)。格子の値の決め方は `ekiwalk` と同じ (同じ 8 点のうち最小)。どの駅でも、駅ごとの値の最小は格子の値と一致する |
| `polygons.py` | 縄張りの面: 格子 (正方形) をまとめた面 → `shapely.coverage_simplify` (40m) → 共有する線ごとに Chaikin 平滑化 (4 回) → 面を組み立て直して持ち主に戻す。帯・15 分超・15 分圏の輪郭も作る |
| `colors.py` | となり合う縄張りの色が重ならない塗り分け (DSatur 法、6 色まで) |
| `stats.py` | 駅ごとの数字: 縄張りの広さ (km²)、縄張りでいちばん遠い所の徒歩分数、縄張りのうち 15 分以内の割合 |
| `export.py` | 画面用ファイルの書き出し |
| `pipeline.py` / `cli.py` | 手順の実行 (`ekiwalk` の手順 → 縄張りの手順) |

### 3.3 eki-walk から消すもの

Overture・N03 の範囲・中心からの最短路・H3 格子・walk15 の画面など、今の walk15 用の処理とテスト
(`sources/overture.py`, `sources/n03.py`, `network/`, `reach/`, `stations/`, `products/walk15/`, `web/walk15/`)。

駅のまとめ方 (600m)、起点の付け方の関数化、縄張りの平滑化。戻すと rail-gap-map の勢力圏の表示もよくなる。

## 5. 計算

- 対象: 東京都 (島しょ部を除く)。計算は 3km 外側まで (`ekiwalk` の設定どおり)。
- 速さ: 80m = 1 分、端数切り上げ。15 分以内 = 1,200m 以内。
- 各格子の値:
  - **縄張りの駅** = いちばん近い駅 (まとめた駅) と、その道のり (`grid-base.npz` の値)。
  - **ほかの駅** = 1,200m 以内に行ける駅と、それぞれの道のり。
- 境界付近の帯: 2 番目に近い駅の道のりが 1,200m 以内で、いちばん近い駅との差が 240m (3 分) 以内の格子。
- 15 分を超える所: いちばん近い駅まで 1,200m を超える格子。

## 6. 画面用のファイル

| ファイル | 中身 | 読むとき |
|---|---|---|
| `territories.geojson` | 縄張りの面 (駅番号・色番号)。平滑化・単純化済み | 最初 |
| `band.geojson` / `far.geojson` | 境界付近の帯 / 15 分を超える所 | 最初 |
| `stations.json` | まとめた駅: 名前・位置・路線・縄張りの広さ・いちばん遠い所・15 分以内の割合 | 最初 |
| `places.json` | 町丁目と駅の検索用 (`ekiwalk` の形式) | 検索を使ったとき |
| `cells/<区画>.json` | 64×64 格子 (1.6km 四方) ごとの、格子ごとの [縄張りの駅, 道のり, ほかの駅, 道のり, …] | 押した所の区画だけ |
| `iso/<駅>.json` | 駅ごとの 15 分圏の輪郭 (平滑化済み) | 選んだ駅・関係する駅だけ |
| `count.geojson` | 15 分以内の駅の数 (切り替え用) | 切り替えたとき |
| `meta.json` | 版・取得記録・計算条件 | 最初 |

大きさの目安は実装時に測り、最初に読むものが合計 5MB (圧縮後 1.5MB) を超えるなら単純化を強める。

## 7. 画面

- 開いたとき: 縄張りの塗り分け、境界線 (濃い灰色)、駅名 (太字、白ふち)、境界付近の帯 (斜線)、15 分超は薄く。背景は OpenFreeMap (日本語の地名)。
- 上のバー: 駅名・町丁目で探す / 現在地 / 表示の切り替え (縄張り・駅の数) / 背景 (地図・航空写真) / このマップについて。
- 地点を押す・検索で選ぶ・現在地:
  - 「ここは ○○駅の勢力圏 (徒歩 6 分)。△△駅 (12 分) の 15 分圏とも重なります」と、駅ごとの分数・距離・路線の表。
  - その駅の縄張りを太線、15 分圏を破線、重なる駅の 15 分圏を別の色の破線で描く。
  - 「勢力圏の駅」は地図に描いた面で決める (見た目と答えを一致させる)。分数は格子の値。境界のすぐそばでは、勢力圏の駅とほかの駅の分数が同じになることがある。
- 駅を選ぶ (駅名を押す・検索): その駅の縄張りを太線、15 分圏を破線で描き、縄張りの広さ・いちばん遠い所の徒歩分数・15 分以内の割合を出す。
- 結果はパソコンでは右、スマホでは下から出す。
- 「このマップについて」: 計算の限界と出典。

## 8. 限界 (画面と docs に書く)

- 道のりは、ホームの線から 100m 以内の道を起点に測っている (駅の出口からではない)。
- 信号待ち・坂・階段・踏切・地下の上り下りは入れていない。80m = 1 分。
- 縄張りの境界は見やすさのために平滑化している (位置のずれは数十 m 程度)。
- 道から 300m を超える所、海・水面は空白。
- 物件広告の「徒歩○分」とは測り方が違う。
- データの日付: OSM 2026-10-01、N02 2025-12-31、N03 2026-01-01、ABR (取得日)。

## 9. 検証

- 単体テスト:
  - 駅のまとめ (600m の境目、名前の違う駅はまとめない)
  - 駅ごとの最小 = 格子の値 (小さな手作りの道路網)
  - 平滑化した面に隙間・重なりがない (面積の合計の一致、面どうしの重なり 0)
  - となり合う面の色が違う
  - 帯・15 分超の判定
- `ekiwalk` との一致: 格子の「いちばん近い駅」が rail-gap-map の作り方と一致すること。
- 実データの点検: 乗換駅 5 組がまとまっていること、都境・川沿い・大きな駅のまわりを画面で見る。
- 画面: パソコン幅・スマホ幅、検索、現在地、切り替え、コンソールのエラーなし。

## 10. やらないこと

名前の違う乗換駅のまとめ (有楽町・日比谷など)、駅の出口データ、信号・坂、経路の線の表示、東京以外、rail-gap-map のコードの変更 (3.4 は後で相談)。
