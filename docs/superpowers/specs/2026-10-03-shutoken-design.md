# 駅の縄張りマップ 首都圏への拡大 設計

- 日付: 2026-10-03
- 状態: 方針は合意済み (計算は県ごとに分ける、画面は必要な分だけ読む、首都圏から順に)。この文書の確認待ち
- 前提: `docs/superpowers/specs/2026-10-03-territory-design.md` (東京版)

## 1. 目的と順番

東京都に加えて、埼玉県・千葉県・神奈川県でも同じ縄張りマップを使えるようにする。1 県ずつ進める。

1. 画面とデータの形を「複数の地域」に対応させる (データは東京だけのまま。見た目と答えが変わらないことを確かめる)
2. 埼玉県を足す → 確かめて公開
3. 千葉県を足す → 確かめて公開
4. 神奈川県を足す → 確かめて公開

公開 (push・gh-pages の置き換え) はそのつど確認を取る。

## 2. 計算: 県ごとの地域 (region)

- 地域 = 1 つの都県。`configs/regions/<地域>.toml` (ekiwalk の形式) と `configs/territory-<地域>.toml` を県ごとに持ち、`eki-walk build` を県ごとに実行する。
- 各地域の表示範囲 = その都県 (N03 のコードの先頭 2 桁)。計算範囲 = 表示範囲を 3km 広げた範囲 (ekiwalk の設定どおり)。県境の外の駅と道も入るので、県境でも「いちばん近い駅」は正しい。
- 格子・駅のまとめ・平滑化・後処理は東京と同じ。駅のまとめ (同名 600m) は地域ごとに行うが、まとめ方は同じ規則なので、県境をまたぐ駅も両方の地域で同じまとまりになる。
- 地域の外接矩形 (`bbox`) は N03 から計算して設定に書く。

## 3. 地域をまたぐ一貫性 (combine の手順)

県ごとに計算したあと、`eki-walk combine` で次をそろえる。

| 項目 | やり方 |
|---|---|
| 駅の共通の ID | まとめた駅を、属する N02 のグループコードの組で表す (`key`)。同じ駅は、どの地域でも同じ `key` になる |
| 色 | 全地域の縄張りを 1 つの隣接グラフにまとめて塗り分ける (同じ `key` は同じ色。県境で接する縄張りも別の色) |
| 地域の一覧 | `data/regions.json`: 地域ごとの名前・表示範囲の外接矩形・データの場所 |

## 4. 画面: 必要な分だけ読む

- 最初に `regions.json` だけを読む。地図に見えている範囲と重なる地域の縄張り・帯・薄い所・駅・範囲を、その地域のぶんだけ読む (動かすたびに足りない地域を足す)。
- 地点を押したとき: その地点を含む地域 (範囲の面で判定) の格子のデータを引く。
- 駅を選んだとき: 同じ `key` の駅を全地域から集め、縄張りの広さは合計、いちばん遠い所は最大、15 分以内の割合は広さで重み付けして出す。縄張りと 15 分圏の輪郭も、その駅がある全地域のものを描く。
- 駅名の点と文字: 地域ごとに、その地域に縄張りを持つ駅だけを出し、同じ `key` は 1 回だけ描く。
- 検索: 初めて検索したとき、全地域の `places.json` を読む (駅は `key` で 1 つにまとめる)。
- URL `?region=` は使わなくなる (試運転用の地域は `regions.json` を切り替えて見る)。

## 6. 限界 (足すもの)

- OSM の関東の抽出には静岡県・山梨県・福島県などが入っていない。神奈川県の西端 (湯河原・箱根) などで、県の外の道がないために縄張りが実際と違うことがある。
- 画面のデータは全体で約 400MB の見込み (東京の約 7 倍)。GitHub Pages の上限 (1GB) には収まる。

## 7. 検証

- 手順 1 のあと: 東京の縄張り・答え・駅の数字が今と同じこと (データの比較と画面)。
- 各県: ekiwalk の格子との一致 (最大の差 0.000m)、乗換駅のまとまり、県境 (例: 赤羽と川口、町田と相模原、葛西と浦安) で縄張りがつながり色がそろっていること、主な駅での答え。
- メモリと時間を記録する (このパソコンは 32GB)。
